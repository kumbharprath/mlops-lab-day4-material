# Day 4 MLOps Workshop — FastAPI + Docker: Student Hands-on Lab Guide

**Topic:** Model containerization and API deployment   
**Environment:** Windows 10/11, Git Bash, Python 3.11, VS Code, Docker Desktop (Linux containers). macOS/Linux alternatives are noted.  
**Project:** Food Delivery Delay Prediction API

> **START HERE:** Extract `Day4_MLOps_Modular_Project.zip`. Open the `mlops-day4` folder in VS Code. Run every terminal command **from inside `mlops-day4`**, unless a step explicitly says otherwise. By the end of this lab, you will be able to (1) explain training vs inference, (2) run a Python REST API using FastAPI and Uvicorn, (3) send JSON requests with Swagger UI, cURL or Postman, (4) validate inputs with Pydantic, (5) work with separately organized data/model/evaluation scripts, (6) build a Docker image, (7) run and inspect containers, and (8) demonstrate host-to-container port mapping.

## Lab 2 — Run your first FastAPI endpoints (2:00–2:15)

`app.py` already contains three routes: `GET /`, `GET /health`, and `POST /predict`. We will learn the GET routes first, then explore the prediction route.

### Step 1. Inspect `demo_app.py`

Notice:

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

demo_app = FastAPI(title="MLOps API Demo")

# Pydantic model for request validation
class Student(BaseModel):
    name: str
    age: int
    course: str


# Temporary in-memory database
students = {}


# GET - Health check
@demo_app.get("/health")
def health():
    return {
        "status": "healthy",
        "model_loaded": True
    }


# GET - Fetch all students
@demo_app.get("/students")
def get_students():
    return students


# GET - Fetch student by ID
@demo_app.get("/students/{student_id}")
def get_student(student_id: int):
    if student_id not in students:
        raise HTTPException(status_code=404, detail="Student not found")

    return students[student_id]


# POST - Create a new student
@demo_app.post("/students")
def create_student(student_id: int, student: Student):
    if student_id in students:
        raise HTTPException(status_code=409, detail="Student already exists")

    students[student_id] = student.model_dump()

    return {
        "message": "Student created successfully",
        "student": students[student_id]
    }


# PUT - Update an existing student
@demo_app.put("/students/{student_id}")
def update_student(student_id: int, student: Student):
    if student_id not in students:
        raise HTTPException(status_code=404, detail="Student not found")

    students[student_id] = student.model_dump()

    return {
        "message": "Student updated successfully",
        "student": students[student_id]
    }


# DELETE - Delete a student
@demo_app.delete("/students/{student_id}")
def delete_student(student_id: int):
    if student_id not in students:
        raise HTTPException(status_code=404, detail="Student not found")

    del students[student_id]

    return {"message": "Student deleted successfully"}   
```

The `@demo_app.get` decorator connects an HTTP GET request to a Python function. FastAPI returns the Python dictionary as JSON. **The dots above are for explanation, not copy-and-paste code**—the complete working application is already in `demo_app.py`.

### Step 2. Run Uvicorn

**Expected:** `Uvicorn running on http://127.0.0.1:8000`. Keep this terminal open. If you need more commands, open **another** Git Bash terminal with `.venv` activated.

### Step 6. Test Pydantic validation with an invalid data type

1. Expand **POST /students**.
2. Click **Try it out**.
3. Enter `2` as `student_id`.
4. Provide the following JSON:

```json
{
  "name": "Amit",
  "age": "twenty",
  "course": "Python"
}
```

5. Click **Execute**.

**Expected:** HTTP **422 Unprocessable Entity**

**Explanation:** The `Student` Pydantic model defines `age` as an integer:

```python
class Student(BaseModel):
    name: str
    age: int
    course: str
```

The value `"twenty"` cannot be converted into an integer, so Pydantic rejects the request.

**Important:** The current model does not prevent negative ages. To add that validation, use `age: int = Field(ge=0)` and import `Field` from Pydantic.

### Step 6. Understand the call chain

```text
train_model.py
  ├── create_dataset.create_dataset()  → DataFrame
  ├── validate_data.validate_dataset() → validated data
```

## Lab 6 — Read and understand the Dockerfile (3:15–3:30)

### Step 1. Open the provided `Dockerfile`

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN python -m pip install --no-cache-dir -r requirements.txt
COPY app.py .
COPY models/ ./models/
EXPOSE 8000
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Why each line exists:**

- `FROM` selects the Python base image.
- `WORKDIR` sets the working directory inside the image.
- `COPY requirements.txt` makes dependency requirements available.
- `RUN` installs runtime packages during image build.
- `COPY app.py` includes the web application.
- `COPY models/` includes the already-trained model file.
- `EXPOSE 8000` documents the container's intended port (**does not publish it**).
- `CMD` starts the web server when a container launches. `0.0.0.0` is required for the intended container networking.

### Step 2. Why don't we copy `scripts/` into the serving image?

Training occurs **before** building the image. The deployment needs `app.py`, runtime packages and the saved `models/delivery_model.joblib`; it doesn't need the dataset generator or training scripts. This makes the separation between **training** and **inference** visible.

### Step 3. Inspect `.dockerignore`

It excludes `.venv/`, caches, Git metadata, tests, training scripts and generated CSV from the build context. Do **not** exclude `models/`.

### Step 4. Confirm artifact exists

```bash

```

If missing, run `python -m scripts.train_model` before the Docker build.

```bash

```

**Expected:** Health response after the restarted API becomes ready. If the request is too early, retry after a moment.

### Step 3. Change host port to 9000

```bash

```

**Explain:** Host port is 9000, while Uvicorn still listens inside the container on port 8000. This is **port forwarding/publishing**.

```bash

```

**Expected:** The container was removed but image `delivery-api:1.0` is still listed. You can start a new container from the same image later.

### Common troubleshooting

| Symptom | What to try |
|---|---|
| `ModuleNotFoundError` | Activate `.venv` and install `requirements.txt` |
| `No module named scripts` | Run commands from project root and use `python -m scripts.train_model` |
| Missing `models/delivery_model.joblib` | Run `python -m scripts.train_model`, then rebuild image |
| `InconsistentVersionWarning` for model | Use pinned `scikit-learn==1.8.0` or retrain in target environment |
| Cannot connect to Docker daemon | Start Docker Desktop; run `docker info` |
| Port 8000 is in use | Stop local Uvicorn with Ctrl+C, or use host port 9000 |
| Container exits immediately | `docker ps -a` then `docker logs delivery-container` |
| Container name already exists | `docker stop delivery-container` followed by `docker rm delivery-container` if appropriate |
| HTTP 404 | Check endpoint URL (`/`, `/health`, `/predict`) |
| HTTP 422 | Check required JSON fields and valid values |
| Source code edits do not affect running container | Rebuild Docker image and recreate container |
